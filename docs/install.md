# Getting started

[Documentation](README.md) · [Portal-NG](../README.md)

## Requirements

Docker Engine 24+ with Compose v2.24+ (or Docker Desktop), about 1 GB of RAM and a few hundred MB of disk.
Rootless Podman works too: see [Deployment](deployment.md#rootless-podman-quadlet).

Nothing else is installed on the host. The images are published on Docker Hub
(`skouedlabs/portal-ng-backend` and `skouedlabs/portal-ng-frontend`) and on `ghcr.io/skouedlabs/` as the
same builds with the same digests, so `docker compose up -d` pulls rather than builds. Add `--build` to
build from the checkout instead.

## First start

```bash
git clone https://github.com/SkouedLabs/Portal.git portal-ng
cd portal-ng
docker compose up -d
docker compose ps        # db, backend and frontend healthy
```

Open **http://localhost:8080** and sign in as `admin` / `admin`.

On first start the backend:

- creates the database schema;
- generates the master key (`/data/secret_key` in the `app-data` volume) if `SECRET_KEY` is not set;
- creates the local super-admin;
- creates a sample "Home" dashboard visible to every signed-in user.

To override any default, copy `.env.example` to `.env` and edit it — every variable is listed in
[Configuration](configuration.md).

## Production checklist

Do these **before** the first start, because some of them cannot be changed afterwards:

- [ ] **Set `POSTGRES_PASSWORD`.** PostgreSQL keeps the password it was initialised with; changing the
      variable later does not change the database.
- [ ] **Set `INITIAL_ADMIN_PASSWORD`**, or set it to an empty value to get a random one printed once in
      `docker compose logs backend`. The default `admin` logs a warning until it is changed.
- [ ] **Set `SECRET_KEY`** (`openssl rand -base64 48`) or let it be generated in the `app-data` volume —
      and then back that volume up. Without the master key, the stored LDAP/OIDC and TOTP secrets cannot
      be decrypted.
- [ ] **Put a reverse proxy in front for TLS** and set `PUBLIC_URL` to the `https://` address users type.
      It drives the OIDC redirect URI, the WebAuthn security keys and the `Secure` cookies. See
      [Deployment](deployment.md).
- [ ] **Restrict the administration by IP** on the proxy (`/admin` *and* `/api/admin/`; examples
      provided).
- [ ] **Plan the backups** of the `db-data` and `app-data` volumes. See [Operations](operations.md#backups).

## Updating

```bash
docker compose pull         # or: docker compose build --pull, to build from the checkout
docker compose up -d
```

The schema is created and extended at startup, so there is no migration step to run. Both volumes are
kept. What an upgrade may require is listed in the [changelog](../CHANGELOG.md).

## Offline (air-gapped) installation

Portal-NG needs **no internet access at runtime**. Everything the browser loads comes from the portal
itself: the application code, the Font Awesome icons and fonts, the icon search index, the TOTP QR codes
generated by the server. No CDN, no external font, no telemetry. The backend only connects to what you
configure: the LDAP directory, the OIDC provider, the applications it checks the status of. Only building
or pulling the images needs the internet.

On a machine with internet access:

```bash
docker compose pull
docker pull postgres:17-alpine
docker save -o portal-ng-images.tar \
  skouedlabs/portal-ng-backend:latest skouedlabs/portal-ng-frontend:latest postgres:17-alpine
# + traefik:v3 if you use example/traefik
```

Copy `portal-ng-images.tar` and this repository to the offline host, then:

```bash
docker load -i portal-ng-images.tar
docker compose up -d --no-build --pull never    # never tries to build or pull
```

Same with Podman: `podman load -i portal-ng-images.tar`, and the Quadlet units already name the published
images (`docker.io/skouedlabs/portal-ng-backend:latest`), so a loaded image is used as it is.

What to plan for offline:

- **Logos and icons of your links**: upload them (the image fields in the administration and the editor)
  instead of pointing at addresses on the internet, or use the bundled Font Awesome icons. Uploaded images
  are stored in the `app-data` volume and served by the portal — see
  [Branding](branding.md#images-and-how-they-are-stored).
- **Certificates**: an internal PKI on the reverse proxy. Import its root CA in Admin › Certificates so the
  backend trusts your LDAPS directory, your identity provider and the applications it probes.
- **OIDC**: the identity provider must be reachable from the backend on your network.

Tested: the stack started on Docker networks with no route to the outside (`internal: true`, no DNS and no
IP egress). A headless browser then went through the sign-in page, the dashboards, the editor, the icon
picker, every administration page, the TOTP enrolment and a Homer import. Result: 0 requests outside the
portal, 0 JavaScript errors, icons and fonts rendered.
